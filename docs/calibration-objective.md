# Критерий калибровки опорного рынка

Черновик для #11. Эталон — закрытия S&P 500 из #4. Подбор выполняется на
2017–2022 годах с одной BS-политикой при базовой комиссии. Опорная конфигурация
используется всеми четырьмя hedge policies. Финансовые допущения и лимиты
сверяются по #5, #8 и #10 перед подбором.

## Целевые статистики

Для каждой конфигурации и каждого общего seed берём одинаковое число дневных
лог-доходностей после burn-in. В расчёт входят реальные нулевые доходности
рынка в дни без сделок. Вычисляем статистики по формулам загрузчика #4 и
усредняем их по seeds с равными весами. Функция потерь — среднее трёх блоков:

- Квадрат относительной ошибки годовой волатильности.
- Среднее квадратов ошибок `p05` и `p95`, делённых на дневную волатильность
  S&P 500 перед возведением в квадрат.
- Среднее квадратов ошибок ACF модуля доходности на лагах 1, 5 и 20.

Сводка хранит как loss, так и расхождения по каждому моменту. Равенство по
loss разрешается по идентификатору кандидата. Кандидат с неполным журналом
или неопределённой ACF (например, при постоянной цене) виден в списке failures.
Доходности отложенного периода не участвуют в отборе. После выбора скрипт
проверяет ту же конфигурацию по данным 2023–2025 на других seeds.

## Прогон после интеграции

Сетка параметров должна оставаться небольшой и фиксироваться до подбора.
Первые кандидаты для согласования — масштабы публичной фундаментальной и
частной компонент сигналов. Исходные коэффициенты пока заданы в коде рынка.
Для grid run их нужно вынести в проверяемую конфигурацию и закрепить единицы.

| Группа параметров | Основание |
| --- | --- |
| Исторические волатильность, хвостовые квантили и ACF | Эталон #4, расчёт из дневных закрытий |
| Гетерогенные агенты и проверка кластеризации | Литература #3, качественная мотивация |
| Масштабы публичной и частной компонент сигналов | Кандидаты для подбора по калибровочному периоду |
| Число агентов, ставки, базовая комиссия и срок call | Сценарные условия #1, сверка единиц #2/#5/#8/#10 |
| Tick, lot, ограничения и модель наблюдаемой sigma | Сценарные условия, единая конфигурация для политик |

Предлагаем использовать `10000–10049` для подбора и `10050–10099` для
проверки. Оба диапазона принадлежат пространству калибровки. В каждом
fit-run после burn-in берём 1 509 торговых доходностей, в holdout-run — 752.
Эти длины соответствуют объёму FRED-периодов. AR/EWMA-оценка в прототипе и
20-дневное выборочное SD в черновике #1 требуют согласования до фиксации
ref-market и генерации #21. Измерение годовой рыночной волатильности для loss
всегда производится по реализованным доходностям, отдельно от входа политики.

## Интерфейс оценки

Сводка FRED — `metadata.json` из #4. `grid-results.json` содержит список
`seeds` и объект `candidates`, где каждому идентификатору кандидата
соответствует объект `seed → сводка доходностей в формате #4`. Рекомендуемый
идентификатор — SHA256 файла параметров кандидата. `holdout-results.json`
содержит `candidate`, `seeds` и `simulations` (`seed → сводка доходностей`).
Сохраните выбранный файл параметров вместе с результатом `rank`.

```bash
uv run python -m finmath.calibration.objective rank \
  data/processed/fred-sp500/metadata.json grid-results.json > selection.json
uv run python -m finmath.calibration.objective holdout \
  data/processed/fred-sp500/metadata.json holdout-results.json selection.json
```

Реальное качество будет проверено после интеграции независимой BS-политики и
портфелей. Итоговый manifest сохранит commit, параметры с единицами и
происхождением, SHA256 FRED и конфигурации, seeds, результаты обоих периодов
и расхождения. Для стилизованного факта сравниваются знак и величина
ACF `abs(r)` по нескольким лагам. Положительная короткая ACF служит
диагностикой кластеризации.
