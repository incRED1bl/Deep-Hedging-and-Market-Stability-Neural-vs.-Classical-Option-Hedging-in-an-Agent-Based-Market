# Реестр экспериментов

Прототип #15 проверяет матрицу из 1 000 сочетаний на отладочных входах.
Один `market seed` повторяется во всех 20 сочетаниях политики и комиссии.
Ключ строки — политика `bs/leland/band/dl`, односторонняя комиссия в целых
базисных пунктах `0/5/10/20/40` и точное целое семя.

## Отладочный запуск

Сохраните 50 уникальных seeds из 1000–1999 как JSON-массив десятичных строк.
Передайте синтетические файлы, предназначенные для отладки. Команды из корня
репозитория:

```bash
uv run python -m finmath.experiments.registry \
  --database artifacts/runner-fixture/runs.sqlite \
  --seeds artifacts/runner-fixture/seeds.json \
  --config crates/market-sim/tests/fixtures/simulation-config.json \
  --data artifacts/runner-fixture/data.json \
  --model artifacts/runner-fixture/model.json \
  --commit "$(git rev-parse HEAD)"
```

Повтор команды на той же базе пропускает `done`. Для повторной попытки после
технической ошибки добавьте `--retry-failed`. Незавершённая транзакция
после прерывания освобождает блокировку. История ошибок остаётся в
`run_errors`, а `runs` содержит итоговое состояние, число попыток, время,
JSON метрик и временных агрегатов. Смена commit, конфигурации, seed-списка
или SHA256 артефактов требует отдельной базы. Отрицательные финансовые
результаты сохраняются как штатные исходы.

## Прогон с Rust-движком

Соберите `cargo build --locked --release -p market-sim --example run_scenario`
в checkout ветки интеграции #29. В предыдущей команде укажите
`integrated-scenario.json` и `prototype-model.json` из Rust fixtures, добавьте
`--market-executable` с путём к `target/release/examples/run_scenario` и
`--simulator-commit` с SHA checkout. Используйте отдельную базу для этого
движка. В провенансе сохраняются commit и SHA256 бинарного файла.

`--limit 20` выполняет до 20 очередных ячеек. В новой базе это четыре
политики на пяти уровнях комиссии с одним и тем же первым seed. В ячейке
runner подставляет комиссию и seed, проверяет непрерывность журнала и
сверяет конфигурацию из записи шага 0. Волатильность берётся из закрытий
после burn-in. Объём считается по двусторонним сделкам и пересчитывается в
акции, комиссии и P&L — из целых денежных единиц журнала. Ошибка сверки
записывается в историю ячейки. Полный временный журнал удаляется после
сохранения агрегатов или записи ошибки.

CLI принимает только fixture seeds. Контрактные hedging errors, итоговый
формат метрик и замер на замороженной модели относятся к #13, #14 и #18.
